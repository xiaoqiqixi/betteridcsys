# 发布门禁与回退

## 当前定位

这是工程预览/测试候选版本，不是可直接收款开通的商业发布。首次测试仅用合成数据，不连接真实支付、客户资料或云平台凭据。用户提供测试机后才单独确认主机、域名、访问方式和操作范围；本项目没有自动部署外部服务器。

## 每次候选发布

1. 确定功能范围、币种/价格来源、已知限制和适用环境。保存源码 commit 与版本号。
2. 从锁文件构建；审查 Go/npm 依赖与镜像漏洞、许可证。基础镜像固定到经验证 digest，不把浮动系列标签当可复现发布锁。
3. 跑单元/接口/前端构建测试与真实 MySQL 集成测试，完成负向权限、CSRF、幂等和并发测试。
4. 审查迁移，先在从备份恢复的隔离实例上执行。记录是否可回滚；不要假设初始 IF NOT EXISTS 迁移支持任意后续 schema 更新。
5. 验证 TLS、来源限制、cookie、CSP、端口、非 root、秘密与日志。禁止带入演示账号或未审查的第三方脚本。
6. 完成备份与恢复演练、容量/压力测试、监控告警接入。生成 SBOM、镜像扫描报告与变更说明。
7. 明确发布/观察/回滚负责人、维护窗口和业务验收。所有未通过项列为阻塞或明确记录范围豁免，不能悄悄打勾。

## 执行与验证

备份 → 确认停写/兼容策略 → 执行迁移 → 启动 API → 检查 readyz → 启动网页 → 用低权限测试账号验证 → 观察错误率/延迟/数据库/登录异常。没有付款提供商时，支付失败关闭是正确行为，不是需要绕过的故障。

## 回退

失败后先停止新增写入，保留日志和失败迁移证据。只有 schema 向后兼容时才直接回退镜像。需要恢复数据库时，应向负责人说明最后备份时点及可能丢失的写入，获得明确批准后按恢复手册操作。不要自动执行 DROP、清空卷、重建库或跳过迁移。

## 真实商业发布的额外阻塞

当前无真实支付或控制器、完整会计账本/对账、邮件验证/恢复/MFA、自助改密、税票政策、可靠异地灾备与经验证的运营恢复体系。必须按实际业务补齐，且由独立审查确认；不能把此项目说明包装成安全认证、支付合规认证或 SLA。
