# 界面维护规范

适用于现有 Vue 客户控制台与管理台。默认中文，英语可切换；采用克制的层级、留白与反馈，保留运营者配置的站点名称、图标、公司信息及蓝／青／紫固定主题。语言与币种独立选择。界面改动必须保留 [财务模型](FINANCIAL_MODEL.md)、[接口约定](CONTRACT.md) 和 [安全边界](SECURITY.md)。

本页维护现有 Core 的界面规则，不将候选版本视为已发布版本。源码验证与人工视觉复验分别绑定实际提交，已执行范围与未覆盖场景见 [验证记录](VALIDATION.md)，不能沿用旧 Release 或单凭测试计数扩大视觉结论。

## 颜色与排版

共享颜色在 [style.css](../frontend/src/style.css) 定义。`--border` 只用于装饰分隔线，不能代替识别输入框所需的 `--control-border`。不同主题边界必须重新解析品牌别名，确保站点主题和嵌套预览一致。

| 用途               | Token / 规则                                                                                                         |
| ------------------ | -------------------------------------------------------------------------------------------------------------------- |
| 正文／次要说明     | `--text-primary` / `--text-secondary`；说明文字不能通过低对比度表达“不重要”                                          |
| 页面／卡片         | `--page-background` / `--surface` / `--surface-subtle`                                                               |
| 控件边界／键盘焦点 | `--control-border` / `--focus-ring`；焦点轮廓 3px、偏移 3px                                                          |
| 品牌               | `--blue` 为主按钮背景，`--brand-ink` 为浅品牌背景上的文字；固定预设不能注入任意 CSS                                  |
| 状态               | `--status-success` / `--status-warning` / `--status-danger` / `--status-neutral`；同时显示文字，不能只用颜色或小圆点 |

普通文字按不低于 4.5:1 检查；焦点与必要的控件识别边界按相邻背景不低于 3:1 检查，不将所有装饰线都视为控件边界。阈值不能四舍五入后判定通过。参考 W3C [文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 与 [非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

`accessibility-tokens.test.ts` 直接读取实际 CSS 的不透明 sRGB 颜色，检查三主题、正文／说明、主按钮／选中态、焦点／边界和四种状态徽标。它不计算截图中的合成、遮挡、渐变或实际字体，不能替代浏览器检查或完整 WCAG 审查。

使用本地系统与中文字体回退，不加载外部字体。正文基线 16px／1.7；关键标签、帮助、表头和操作按钮为 14px。中文标题使用自然字距；金额与标识可保留独立数字或等宽样式。长站点名、中文说明及错误必须换行，不靠截断隐藏关键含义。

## 导航、表单与状态

- 1024px 及以下采用抽屉导航，1025px 起显示常驻侧栏：关闭抽屉时 `inert` 并从辅助技术隐藏；打开时聚焦导航并限制 Tab 范围，主内容暂时 `inert`。Escape、遮罩与可见关闭按钮返回触发器，路由完成后聚焦主内容；跨断点恢复桌面语义并处理焦点。卸载时移除媒体查询监听器。720px 仍为手机页头和内容重排断点，与导航断点独立。
- 保留可见键盘焦点与跳转主内容入口。主按钮和移动导航按钮以 44px 为项目舒适目标；WCAG 2.2 最低目标尺寸规则为 24px 并含间距例外，不能把所有小于 44px 的控件直接判定违规。参考 [可见焦点](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html) 与 [目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。
- 每个输入具有可访问名称；重复的币种与套餐控件必须包含对象上下文。相关控件使用命名分组；错误由稳定 ID 与 `aria-describedby` 关联，并设 `aria-invalid`。校验失败聚焦首个可操作错误。只读值仍可选取复制，说明为何只读。
- 校验长度遵循服务端 UTF-8 字节边界，不能用字符数冒充。SMTP 凭据成对更新、连接目标变更和清除条件保持原规则。错误只显示固定安全文案，不显示提供方响应、密码或秘密；无明确字段证据时不能声称“已标注字段”。
- 请求期间清楚展示加载或刷新；缓存账单仍可读，但须标识正在更新。成功、失败、关闭、卸载和账户变化都要收束状态，过期请求不得覆盖当前对象或新账户。保存或邮件结果不明时要求先核对，不自动重试。
- 未付取消继续使用已有原生确认对话框，显示具体订单和后果；保持服务端事务、权限及幂等约束，不把视觉隐藏当作授权。

## 抽屉与任务弹窗

- 抽屉采用品牌／工作区、服务导航、账户与支持三段，账户身份和连接提示集中展示；不靠新增统计或虚构入口填空。短屏后台导航可独立滚动，账户区不能覆盖既有条目。关闭按钮保持可达，路由、返回、Escape、遮罩及焦点回归沿用原交互规则。
- 原生 `<dialog>` 保留可访问名称与原有关闭／保存约束。标题区、可滚正文、操作区分层，使用共用颜色 token；不再用重复标题与双层白框堆层级。不能为新外观替换支付、取消、异步刷新或焦点脚本。
- 账单唯一总额紧随编号和状态，开具方、历史日期／币种、完整项目逐项保留。长前后缀、合法最大金额和标识必须换行可读，不用省略号、缩小字号或隐藏溢出冒充修复。金额仍取原记录的币种与格式快照。
- 手机及横屏的操作区须有高度边界与可滚能力，保证正文、关闭、服务商入口、完整安全说明和税务提示均可达。不能只在 375×844 正常金额下判定通过；还须检查 320px、375×480、844×375 和长金额。固定头部／操作区不能吞掉正文或覆盖确认说明。
- `frontend/tests/overlay-boundaries.mjs` 由现有 e2e 入口调用，维护金额全字串与 Range 几何、键盘／关闭、抽屉导航／返回、短屏操作区检查。隔离合成支付准备响应不访问提供商，不代表真实付款验证；不增加正式 30 张截图清单，不改变原 50 组响应式或 28 组 checkout 断言。

## 管理员工作台

- 管理员服务入口必须读取全站管理员 API，客户入口继续只读本人；后台需要的归属字段只在管理员响应投影中提供，不为方便展示而扩大客户接口。
- 客户名、邮箱和原始客户 ID 分层显示；资料未载入与客户不存在不同，不猜归属或回填成当前管理员。长 ID/邮箱可换行复制，归属标签保持横排可读，桌面同行卡片的金额区对齐。
- 明确清单上限与当前搜索范围。首次失败不制造“没有服务”，刷新失败保留可读缓存并提示可能过期；不能让服务页错误回落成 404 或客户购买引导。
- 角色与账号共同决定缓存寿命；同一 ID 降权也清空管理员数据、关闭相关任务并拒绝迟到响应。浏览器展示保护不替代服务端当前角色检查。
- 订单状态是业务结果，不是装饰性下拉框；取消、收款、退款应分别有真实接口和一致性记录。未实现的客户/商品/资源管理不得用假按钮填满后台，范围见 [管理员管理边界](ADMIN_MANAGEMENT.md)。
- `frontend/tests/admin-management-boundaries.mjs` 在原 e2e 中独立维护 6 个合成场景，不混入原 50/28/15 计数、不增加正式截图清单。真实 MySQL 权限证明与合成浏览器展示证明分别记录。

## 业务文案的事实边界

“选购套餐”进入报价与订单确认；不能称为立即创建真实服务器。支付通过运营者与开发者提供的第三方渠道适配器扩展，当前默认关闭；真实接口、现有结账边界和待补齐的回调入账要求见 [支付插件接入说明](PAYMENT_PLUGINS.md)，不能把返回地址跳转当作付款成功。默认 CNY、运营者独立币种及价格、订单历史币种和套餐快照不能被 UI 修改为自动换汇或按当前格式重写。

SMTP 的已保存、插件可用、连接目标已批准、服务器已接受与最终送达是不同状态。主机的已准备、已计划、执行中、已验证回执与业务可用也不同；Web 只能读取受限事实，不运行 root 命令。样式和动画不得暗示后台未完成的操作成功。

## 合并与发行验证

先运行前端类型、组件回归、格式和生产构建，再在允许的隔离云环境执行浏览器脚本；同时验证桌面、1024/1025px 导航边界、720/721px 手机内容边界、窄屏、键盘、三主题、长中文、空态、错误及请求中状态。测试只能连接回环合成数据，不能指向业务服务。

实际浏览器功能结果、截图元数据和人工看过的截图分别记录到 [验证记录](VALIDATION.md)。视觉验收必须实际打开桌面／手机截图，检查溢出、遮挡、焦点、层级、对比度和错误可见性；文件存在、数量或摘要都不能替代看图。历史环境的 Chromium 沙箱或截图限制不能自动沿用于新环境，也不能靠关闭沙箱或变换下载路径绕过限制；各次记录须明确真实浏览器、沙箱、运行平台及证据边界，不据此扩大为完整发行验收。
