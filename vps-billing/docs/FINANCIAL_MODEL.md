# 财务配置、独立报价与历史约束

Core 0.5.0 聚焦币种、价格、订单与账单的财务一致性。全新安装只有 CNY（人民币、前缀 ¥、小数位 2、启用且默认），示例套餐仍需审核后启售。升级保留原 USD 报价、业务历史及合法默认币种；不因新默认值删除 USD 或转换旧金额。这里没有汇率、换汇、跨币种余额迁移或“按默认币种汇总”的折算。

## 运营配置顺序

1. 在管理员“财务设置”核对当前币种清单与默认币种；只有管理员能够修改。新增币种明确代码、名称、前缀/后缀、小数位、排序与启用状态，先保存币种再配置价格。
2. 切换到套餐价格，逐币种输入经过审核的**独立报价**。金额为十进制字符串，不能把另一币种金额换个符号当作新价格，也不能使用汇率自动生成。
3. 核对套餐总开关、该币种报价开关与币种启用状态。三者均允许且报价存在时才能下单；套餐总开关影响该套餐的全部币种。
4. 检查客户报价、按币种概览与新订单快照。保存采用 revision 冲突控制；发生冲突应重新加载并核对差异，不覆盖别人修改。

后台支持现有套餐的分币种价格调整，不提供套餐创建、规格编辑或自动资源开通。缺失报价显示为空且不可售；旧 `plans.price_minor/currency` 仅兼容字段，不能作为新订单定价来源。日常价格管理使用管理员接口，不直接修改 SQL 绕过校验、锁与审计。

## 币种及精度规则

| 字段 | 规则 |
|---|---|
| code | 3 个大写 ASCII 字母，唯一；登记后不允许删除或改名为另一码；不是对 ISO 名录或监管资格的认证 |
| name | 非空纯文本，最多 80 字节 |
| prefix / suffix | 各最多 24 字节纯文本，可为空；仅用于显示，不改变币种身份或金额 |
| decimal_places | 0–6；已有价格、订单、账单或服务记录后永久锁定，停用也不解锁 |
| enabled / default_currency | 默认项必须启用；至少保留一个可用默认项；清单最多 32 个币种 |
| sort_order | 0–10000；相同排序值按代码排序 |

币种清单包含停用项，供历史读取；客户新报价选择器只展示启用项。更改默认币种影响后续缺省选择，不改变任何已有订单/账单。已有币种即使未使用也不能删除；代码不会因修改显示名称或符号而改变。

每笔金额以整数最小单位保存，正价格上限为 `9007199254740991`，实际单位由同条记录的小数位确定。例如精度 0 的 `123` 表示 123，精度 3 的 `1234` 表示 1.234。输入 `1.234` 只适用于至少 3 位的币种；不会舍入成 1.23。拒绝零价、负数、符号、指数、前导零、超出精度的小数和超范围整数。较少小数位可补零，例如精度 2 的 `12.3` 保存为 1230。

一旦建立价格行即锁定精度，即使报价不可售也一样。初始 CNY 已有示例价格，因此精度已锁定。需要不同精度时不能重解释旧整数；应先确定真正不同的业务币种定义，而不是改码绕过历史义务。

## 停用与未完成义务

服务端在事务内检查当前使用情况。存在以下任一项时停用返回 `409 CURRENCY_IN_USE`，同时给出该币种使用计数：

- `pending_payment` 订单；
- `unpaid` 账单；
- 任何非 `terminated` 服务，包括 pending、active 和 suspended。

修改默认币种、关闭套餐或价格不会消除这些义务。当前没有完整取消、退款、结清或终止操作流程，不能通过直接改 SQL 状态、删除记录或强行转换币种来解除阻止。停用只禁止新订单，不删除历史，仍按原币种读取账单和金额。

## 订单、账单及套餐快照

新客户端展示套餐的 `price_revision`，下单始终带 `quote:{price_minor,decimal_places,price_revision}`。核心在锁内发现价格、精度或版本变化时返回 `409 PRICE_CHANGED`，不创建财务记录；界面重新展示报价，需用户确认后再提交。超时结果不确定则保留原键及原 quote 重试，不能直接换价换键。quote 是首次执行条件，已完成的幂等重放优先返回原历史。为兼容旧 API 客户端，quote 仍可省略；这类请求按执行时价格成交，不能宣称具备同样的陈旧报价保护。

新订单在事务内读取所选币种、套餐和独立报价，并连同账单、幂等记录、审计与 outbox 一起提交。订单、账单和服务的 `currency_format` 保存 `{code,name,prefix,suffix,decimal_places}`；展示使用各记录快照，不套用今天的币种格式。金额、币种及开具方身份也不会随当前设置或价格改写。

新订单的 `plan_snapshot` 保存套餐 ID、名称、CPU、内存、磁盘、流量、区域与 `billing_cycle=monthly`。它记录当时选购规格，不表示续费引擎或资源已开通。历史订单缺失的套餐快照保持缺失，不用当前套餐补造过去规格。

迁移 007 对旧 CNY/USD 记录仅补入该旧版本明确的两位小数格式，不引用运营者后来修改的显示设置。旧 issuer 缺失仍保持缺失。订单幂等指纹包含币种；同键改变币种、套餐或 hostname 返回冲突，不重新定价旧订单。不确定提交继续使用原键和原请求，浏览器刷新丢失客户端状态时先查订单历史。

概览金额仅在同币种内汇总；客户数是全局数量，最近订单可能跨币种，但每行独立标示。列表仍最多 1,000 条，没有完整分页/导出合同，不能把列表求和代替财务汇总。

## 数据库与审计边界

迁移 1–6 保持原文；迁移 007 新增 `currency_settings`、价格 revision 与快照列，当前 schema 共 14 张基础表。数据库约束验证代码为三个大写字母和金额整数边界；**是否属于运营方已登记币种由核心事务校验**，数据库不是完整币种注册表外键约束。绕过 API 的直接 SQL 仍可破坏业务一致性，因此运行身份、迁移身份和备份身份必须分离。

币种和价格修改与审计同事务，版本冲突拒绝；两类配置分别维护 revision，价格 revision 为跨币种共享值。默认币种调整还会同步站点设置，已打开的旧表单可能产生合理冲突。审计不是不可篡改会计账本。

## 当前能力与后续财务审计

已实现的重点是独立报价、精确金额、不可变历史、事务幂等、权限与配置审计。实际测试和迁移恢复结论绑定 [验证记录](VALIDATION.md) 的提交，不从旧版本通过结果推导 007 已验收。

下一阶段财务审计应分别评估：订单/账单状态与取消或作废规则；续费周期和欠费处理；退款/贷项、税费与折扣；不可变会计分录和对账；完整分页导出、保留和恢复策略。上述能力当前没有完整实现。本阶段不实现支付渠道、主控/被控或资源开通，SMTP 也不承担账单通知。正常 Release、精度校验或测试通过均不表示生产可运营。
