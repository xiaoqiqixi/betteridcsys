# 商品分类：类型 → 地区 → 套餐

这是 `main` 的未发行功能（schema 11），不是对已发布 v0.5.7 的重新声明。没有线路或节点层；不包含资源开通、汇率换算或新支付渠道。

## 购买与管理

- 客户依次选择类型、该类型下的地区、套餐；类型与地区按后台排序显示。只展示有已上架商品的分类，不增加“全部地区”或比较入口。
- 改选上游分类会清除不再适用的套餐及确认状态。币种默认沿用站点 CNY 设置；没有该币种报价的套餐不可购买，不自动换算。
- 管理员在 **商品管理 → 类型与地区** 新增、改名、排序、启停；填写操作原因后统一保存。商品编辑表单选择所属类型和地区，新增、复制草稿、独立报价及上下架沿用原入口。
- 同名地区可分别属于不同类型，身份由稳定 ID 决定。不能删除仍被草稿或在售商品引用的分类，也不能迁移被引用地区的父类型；停用在售分类前必须先下架其商品。不是删除订单或批量改写历史。
- 保存采用 revision 检查。冲突先重读，不自动重试；网络结果不确定时先核对再操作。语言/币种设置不充当商品分类管理入口。

## API

| 路由 | 权限与用途 |
| --- | --- |
| `GET /api/v1/catalog-taxonomy` | 公开、仅启用类型及其启用地区 |
| `GET /api/v1/admin/catalog-taxonomy` | 管理员、完整注册表 |
| `POST /api/v1/admin/catalog-taxonomy` | 管理员、CSRF/同源检查、完整注册表更新与事务审计 |

GET 返回 `data: {revision, types, regions}`。类型字段为 `{id, name, sort_order, enabled}`，地区另有 `type_id`。POST 提交上述完整字段并增加 `reason`；不是局部 patch。服务端生成下一 revision，数组按 sort_order、ID 排序。

- 最多 128 类型 / 512 地区；ID 为 1–64 位 ASCII 字母、数字、`_`、`-`、`.`，不能单独为 `.` 或 `..`。
- 类型名先去首尾空白，1–120 UTF-8 字节。地区名保留原文，必须非空白，最多 480 字节且 120 Unicode 字符；排序为 0–1,000,000 整数；原因去首尾空白后 1–500 字节。
- 专用分类 POST 最大 1 MiB，其他既有财务请求体上限不变。重复/缺失/未知/null 字段、重复 ID、不存在的父类型均拒绝。
- `INVALID_TAXONOMY` 为 400，`TAXONOMY_CONFLICT` / `TAXONOMY_IN_USE` 为 409。拒绝不产生部分分类更新或成功审计。
- `/plans` 仍为数组，每项新增 `type_id`、`region_id`、`taxonomy_revision`。前端将其与公开注册表交叉验证；两个 GET 的 revision 不同则提示重读，不猜测父级、不自动重放写入。
- `/admin/catalog` 返回新增 `taxonomy_revision`，商品新增两个分类 ID。创建/编辑必须同时提交 `taxonomy_revision`、`type_id`、`region_id`，原 `region` 必须与注册表原文一致。复制提交分类 revision 并保留源分类；旧的缺字段请求明确拒绝，不隐式绕过分类。

## 财务与并发边界

分类更新在同一事务中递增 taxonomy revision 及现有全局报价 revision，使旧报价不能被新订单继续使用；不改报价金额。地区改名只更新当前商品的地区文字。订单、账单、历史币种格式与 `plan_snapshot` 不改；先前合法幂等请求仍返回原订单。新订单只增加分类可售校验，金额解析、独立币种报价、幂等键、支付及历史快照生成逻辑不替换。

管理员身份在持锁事务内重新确认。锁序维持用户 → 币种 → 分类 → 商品。成功更新记录 `catalog.taxonomy_updated`，不把业务事件 ID 当作 HTTP 请求 ID。

## 升级与回滚

新增 `011_catalog_taxonomy.sql`（三张分类表、plans 两个分类字段与外键）。001–010 原文不改。旧商品映射至“通用服务器”，按地区原文字节生成确定地区 ID，不从商品名称猜测类型；价格和历史记录不重建。过多或不合法旧地区在 DDL 前拒绝，需要先明确修复数据再升级。

上线前先完成可校验备份、读取迁移/preflight，迁移后重复检查 schema 11。旧 schema10 二进制不能直接读取新库；回滚必须停止写入并恢复升级前备份及对应旧二进制，**不能删除版本记录或伪降 schema**。参考 [升级](UPGRADE.md)、[备份恢复](BACKUP_RECOVERY.md) 和 [验证记录](VALIDATION.md)。本功能的本地检查不自动等同于发行产物验收。
