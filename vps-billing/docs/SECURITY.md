# 安全边界与威胁模型

## 保护对象与信任边界

保护客户账号、会话、账单金额、订单所有权、数据库凭据、审计和未来开通事件。浏览器完全不可信，不能信任客户端提交的价格、客户 ID、角色或“支付成功”状态。API 与数据库网络是不同边界；只有应用身份可使用业务数据库。Docker/宿主机管理员拥有高权限，容器加固不能代替主机安全。

本版本不收集卡号，不存储银行卡或云平台密钥，不发送真实控制器动作。不要添加“后台手动改已支付”作为临时支付绕过。

## 攻击面与必须验收的控制

| 风险 | 设计控制 | 剩余风险 / 验证要求 |
|---|---|---|
| 跨租户读写 / IDOR | 服务端会话身份、资源所有权查询、管理员 RBAC | 必须用两个客户的真实 MySQL 数据验证每个资源与列表；隐藏按钮不算权限 |
| CSRF / 会话劫持 | HttpOnly cookie、生产 Secure、SameSite、变更请求 CSRF 与来源限制 | XSS 可绕过部分浏览器控制；检查注销、过期和错误来源 |
| XSS / 点击劫持 | Vue 转义、脚本 CSP self、禁止嵌入、禁止 MIME 嗅探 | 动态样式允许 inline；新增富文本、CDN 或支付 SDK 必须单独审计 |
| 重放 / 双击重复订单 | Idempotency-Key、数据库事务与唯一约束 | 并发与冲突载荷必须在真实 MySQL 上测试，不能只测内存 |
| 篡改金额 / 越权套餐 | 服务端定价，整数最小货币单位 | 税、折扣、退款、多币种和完整会计分录尚不支持 |
| 伪造付款与开通 | 未配置支付时 fail closed；outbox 不连接真实控制器 | 支付 webhook 验签、去重、金额币种校验、对账和消费重试尚未接入 |
| SQL 注入 | 数据访问使用参数化查询；输入限制 | 后续动态排序/过滤字段必须白名单，审查错误响应是否泄露 SQL |
| 凭据泄露 | 随机秘密、文件挂载、仓库忽略、非 root API、数据库不发端口 | 文件不是 secret manager；主机备份、日志、镜像上下文仍需审查 |
| 暴力登录 / 滥用 | 服务端限速和请求大小限制应验证；边缘补充保护 | 内存限速不能实现多实例全局限速，也不是 DDoS 防护；已配置 nginx 单一 /32 可信来源和覆盖 X-Real-IP，真实 NAT/边缘信任链仍须测试 |
| 数据破坏 / 丢失 | 持久卷、事务、备份及隔离恢复流程 | 尚无自动异地备份、PITR、复制或高可用；卷不等于备份 |
| 内部误用 / 审计删除 | 审计事件与最小权限 | 同库审计不是不可篡改账本；需要独立日志保留和运维审计 |

这里列出的“设计控制”必须以代码和验收结果证实；没有测试证据的控制不能视为已获生产保证。

## 最小权限与部署加固

- 应用和 nginx 以非 root 运行、只读根文件系统、drop ALL capabilities、no-new-privileges。
- MySQL 官方镜像首次启动可能使用 root 初始化后降权，不宣称所有初始化步骤均为非 root。
- Compose 将 `aster_migrator` 的 DDL 迁移身份与 `aster_runtime` 的 SELECT/INSERT/UPDATE/DELETE 身份分离；API 不挂载迁移或 root 秘密。此配置仅在全新数据卷初始化时建立，已有卷升级需 DBA 单独执行。真实 MySQL 运行验证仍需确认 runtime 无法执行 CREATE/DROP/ALTER/GRANT。
- 不发布 API / MySQL 端口，不开放 Docker socket，不以 privileged 运行。
- 生产 TLS、防火墙、SSH 权限、磁盘加密、日志保留、密钥轮换、依赖扫描与告警属于必须补齐的环境控制。
- 演示账号和内存模式不得出现在公开生产环境。不得通过设置 demo 来绕过生产配置错误。

## 账号生命周期缺口

没有邮件所有权验证、密码找回、MFA、自助改密、完整会话管理与账号封禁流程。在这些能力落实前，不适合公开自助商业注册。管理员必须使用独立强口令；通过 CLI 初始化不等于已完成安全的长期管理员管理流程。

## 支付和控制器上线前的独立门禁

1. 选定服务商、产品与真实币种，并明确付款成功的权威事件来源。
2. webhook 原始请求签名、时效、防重放、唯一事件 ID、金额/币种/商户/订单绑定校验。
3. 付款到账与账单状态/审计/outbox 在事务内一致更新；异常回调不可改变状态。
4. 实现幂等 outbox worker、失败重试上限、死信、运维恢复、控制器幂等键及状态对账。
5. 退款、争议、取消和失败开通的业务政策经人工确认并实现，不能由演示 UI 推断。
6. 在服务商沙盒和受控测试资源上验收，再另行授权真实收款与真实开通。

## 事故响应草案

发现越权/泄露时先阻止受影响入口和进一步写入，保留证据，不急于清空日志或删库。界定影响范围与起止时间、冻结相关会话、轮换泄露密钥、验证修复和恢复完整性。通知责任人与受影响方的流程、保留期限及适用要求需由实际运营方确定。不要把本说明当作法律或合规认证。
