# 安全边界与威胁模型

## 保护对象与信任边界

保护客户账号、会话、账单金额、订单所有权、数据库凭据、审计和未来开通事件。浏览器完全不可信，不能信任客户端提交的价格、客户 ID、角色或“支付成功”状态。当前目标为单机原生 Linux：systemd 管理 Go API、Nginx 提供 HTTPS 和静态网页、同机 MySQL 持久化。各服务使用独立身份；主机管理员仍具有高权限。多节点和高可用不在本次范围。

本版本不收集卡号，不存储银行卡或云平台密钥，不发送真实控制器动作。不要添加“后台手动改已支付”作为临时支付绕过。

## 攻击面与必须验收的控制

| 风险 | 设计控制 | 剩余风险 / 验证要求 |
|---|---|---|
| 跨租户读写 / IDOR | 服务端会话身份、资源所有权查询、管理员 RBAC | 必须用两个客户的真实 MySQL 数据验证每个资源与列表；隐藏按钮不算权限 |
| CSRF / 会话劫持 | HttpOnly cookie、生产 Secure、SameSite、变更请求 CSRF 与来源限制 | XSS 可绕过部分浏览器控制；检查注销、过期和错误来源 |
| XSS / 点击劫持 | Vue 转义、脚本 CSP self、禁止嵌入、禁止 MIME 嗅探 | 动态样式允许 inline；新增富文本、CDN 或支付 SDK 必须单独审计 |
| 重放 / 双击重复订单 | Idempotency-Key、数据库事务与唯一约束 | 并发与冲突载荷必须在真实 MySQL 上测试，不能只测内存 |
| 篡改金额 / 越权套餐 | 服务端 CNY/USD 独立价格，整数最小单位，币种纳入幂等请求 | 无自动汇率/换汇；税、折扣、退款和完整会计分录尚不支持 |
| 运营设置注入 / 越权覆盖 | 管理员 + CSRF + revision；设置/审计同事务；纯文本与 logo/theme 白名单 | 无 HTML/CSS/脚本或远程图片；支持链接仅展示不抓取，仍需运营方核对目标归属 |
| 历史身份 / 币种被改写 | 创建订单和账单时保存金额、币种与 issuer 快照 | 老数据缺快照时保持缺失；修改公司名不补写历史；账单不是税务发票 |
| 伪造付款与开通 | 未配置支付时 fail closed；outbox 不连接真实控制器 | 支付 webhook 验签、去重、金额币种校验、对账和消费重试尚未接入 |
| SQL 注入 | 数据访问使用参数化查询；输入限制 | 后续动态排序/过滤字段必须白名单，审查错误响应是否泄露 SQL |
| 凭据泄露 | 随机秘密、受限配置文件、仓库忽略、非 root API、数据库不对外监听 | 文件不是 secret manager；主机备份、日志、发布归档仍需审查 |
| 暴力登录 / 滥用 | 服务端限速和请求大小限制应验证；边缘补充保护 | 内存限速不能实现多实例全局限速，也不是 DDoS 防护；已配置 nginx 单一 /32 可信来源和覆盖 X-Real-IP，真实 NAT/边缘信任链仍须测试 |
| 数据破坏 / 丢失 | MySQL 持久数据目录、事务、备份及隔离恢复流程 | 尚无自动异地备份、PITR、复制或高可用；本机数据目录不等于备份 |
| 内部误用 / 审计删除 | 审计事件与最小权限 | 同库审计不是不可篡改账本；需要独立日志保留和运维审计 |

这里列出的“设计控制”必须以代码和验收结果证实；没有测试证据的控制不能视为已获生产保证。

## 最小权限与部署加固

- API 使用无登录权限的 `aster` 身份，发布文件归管理员所有；systemd 模板限制写入、设备、内核接口和 capabilities。API 持久状态在 MySQL，无需可写发布目录。
- Nginx worker 和 MySQL 使用各自的系统身份；发行版 Nginx master 可能需要权限读取 TLS 密钥和绑定 443，不宣称全部原生服务以非 root 启动。按发行版服务模型验证实际权限。
- 数据库迁移身份仅用于本库 DDL，运行身份仅授予本库 SELECT/INSERT/UPDATE/DELETE；API 不可读取迁移、备份或 root 凭据。账号和授权由获准管理员在原生实例配置。
- 原生同机 Unix socket 使用显式 `MYSQL_ALLOW_INSECURE=true`，因为当前驱动配置要求 TLS 或这个例外。此开关自身不会强制 Unix socket；须复核 DSN 确为 `unix(...)`、socket 访问权限与账号绑定，禁止据此启用明文 TCP。跨主机扩展须重新审查 TLS 与信任边界。
- API 只监听回环；MySQL 不对外监听。禁止向 API 身份开放主机管理 socket、sudo 或服务管理权限。
- 生产 TLS、防火墙、SSH 权限、磁盘加密、日志保留、密钥轮换、依赖扫描与告警属于必须补齐的环境控制。
- 演示账号和内存模式不得出现在公开生产环境。不得通过设置 demo 来绕过生产配置错误。

云端 Ubuntu 24.04 已实际验证 systemd API、Nginx HTTPS、数据库与文件权限、API 重启、同二进制/schema 的发布目录切换及同实例新空库备份恢复，证据与源码对应关系见 [VALIDATION.md](VALIDATION.md)。该结果使用临时私有 CA 和合成数据，不涵盖实际域名、公共证书签发/续期、MySQL 进程或整机重启、跨版本迁移回退、独立实例/异地恢复及生产 RPO/RTO；宝塔适配亦未在实际面板主机验证。

## 账号生命周期缺口

没有邮件所有权验证、密码找回、MFA、自助改密、完整会话管理与账号封禁流程。在这些能力落实前，不适合公开自助商业注册。管理员必须使用独立强口令；通过 CLI 初始化不等于已完成安全的长期管理员管理流程。

## 官方 SMTP 的权限与秘密边界

SMTP 默认关闭，只允许管理员在会话、CSRF、来源及 revision 校验下保存配置和主动测试。用户名/密码只写，数据库仅保存二者的 AES-256-GCM 密文；管理读取仅给出配置标志，公开设置不暴露 SMTP 配置。更换目的地主机、端口或 TLS 模式必须替换两项凭据或同时清除并关闭。

本机密钥必须是受限的 32 字节原始文件；未设置时不能启用/发送，设置无效文件会拒绝启动。加密不能防御已控制运行身份或主机管理员的攻击者；同一主机运行进程需要能解密凭据。密钥必须与数据库分开备份，轮换不自动重加密；操作见 [备份恢复](BACKUP_RECOVERY.md#smtp-密钥备份恢复与轮换)。

SMTP 允许管理员指定同机、私网或公共服务器，是受控的出站连接能力；当前没有内置目的地白名单或出口防火墙。仅配置获准目标，审查主机出口和 DNS。所有目标都要求 TLS 1.2 以上、有效证书链与主机身份，认证不降级明文；不提供跳过校验开关。不要将用于展示链接的公共域名限制误认为 SMTP 的网络限制。

测试限定单个收件人和固定内容，每进程至少间隔 30 秒且仅一个在途请求；没有批量、队列、通知或密码重置能力。请求审计在发信前持久化，结果审计为有界尽力写入；SMTP 接受不能回滚。错误仅显示分类，不记录 SMTP 密码、用户名、密文、收件地址、正文或服务商原始回复。结果不确定时先核对服务器记录，禁止自动重发。

`EMAIL_PROVIDER=email.disabled` 不是此插件的停用开关。常规停用应在管理设置关闭；强制阻断新发送可移除 `SMTP_ENCRYPTION_KEY_FILE` 并重启 API。已开始的请求可能使用此前读取的配置，停机中断也可能留下投递不确定性，必须核对结果。真实服务商连通性、DNS 邮件政策和收件箱投递不由本地 TLS 测试证明。

## 支付和控制器上线前的独立门禁

1. 选定服务商、产品与真实币种，并明确付款成功的权威事件来源。
2. webhook 原始请求签名、时效、防重放、唯一事件 ID、金额/币种/商户/订单绑定校验。
3. 付款到账与账单状态/审计/outbox 在事务内一致更新；异常回调不可改变状态。
4. 实现幂等 outbox worker、失败重试上限、死信、运维恢复、控制器幂等键及状态对账。
5. 退款、争议、取消和失败开通的业务政策经人工确认并实现，不能由演示 UI 推断。
6. 在服务商沙盒和受控测试资源上验收，再另行授权真实收款与真实开通。

## 修复与发布范围

维护版本修复强制 MySQL TLS 配置允许明文回退、IPv6 文本别名绕过进程限速、错误 JSON 媒体类型被接受、管理端账单详情所有权路径错误、迟到账单响应覆盖弹窗、同秒备份文件名覆盖等具体问题。新增设置输入/权限/并发审计、精确 CNY/USD 定价及不可变身份的回归测试。测试通过只覆盖已执行路径，真实结果和剩余扫描/部署限制见 [VALIDATION.md](VALIDATION.md)。

公司名/地址/署名是纯文本；不接受尖括号、控制或格式字符。链接限制 HTTPS 公共形态 ASCII 域名，拒绝 IP、localhost、单标签、凭据、端口和片段；服务器不主动访问该地址。logo 和 theme 仅预设值，不提供通用上传/URL 代理。公开设置不会泄露邮件署名和账单地址；后端设置不是 DNS、TLS 或认证来源配置。

核心只支持 CNY/USD，两者均用整数分，拒绝不支持的币种与超精确范围值。单币种聚合不混加，设置变更不能修改历史金额/币种/身份。未来支付插件仍需由核心验证这些值；禁用适配器不会生成已付状态。语言切换不承担金融权威。

## 事故响应草案

发现越权/泄露时先阻止受影响入口和进一步写入，保留证据，不急于清空日志或删库。界定影响范围与起止时间、冻结相关会话、轮换泄露密钥、验证修复和恢复完整性。通知责任人与受影响方的流程、保留期限及适用要求需由实际运营方确定。不要把本说明当作法律或合规认证。
